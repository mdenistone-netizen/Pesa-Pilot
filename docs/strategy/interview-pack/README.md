# P4 Interview Pack: for owner review

**Status:** **draft, waiting for owner review.** Do **not** recruit anyone or collect any information until the owner approves this pack.

**Plan it implements:** `../VALIDATION_PLAN.md` (DEC-023, re-aimed by DEC-024).

## The questions this research must answer
1. **Will ordinary users consistently record transactions manually?** Measured by behaviour over 7 days, not by asking.
2. **What makes them stop?** Moments, reasons, effort.
3. **What would make recording easier?** Observed friction points first, then their ideas second.
4. **How do people check balances today, and how do they find forgotten transactions?**
5. Do they have the core problem ("I don't know what's free; I run out before the next money"), and does seeing "free to use" change decisions?

## Boundaries (non-negotiable)
- **No payments, pre-orders or price commitments.** Price questions are asked only as opinions, to choose test prices later (VALIDATION_PLAN §6.1).
- **Nothing is collected about M-Pesa messages,** and participants are never asked to share them (DEC-024).
- **Participants' preview data never leaves their phone.** We learn only what they *tell us* or *choose to show on screen*.
- **No PINs, ID numbers, statements or exact balances are written down.**
- **Notes use participant codes** (P01…) and are stored outside the public GitHub repository. Only an anonymised summary is added to the repo.
- **Quick entry, balance check-ins and recurring entries are not in the app.** In this research they appear only as **ideas described in words or on paper** (test script part D), never as working features.
- **The balance-check-in idea is always described with its rule:** an unexplained difference would be recorded as a clearly labelled, traceable, reversible "unrecorded spending" entry. **PesaPilot never invents transaction details.**
